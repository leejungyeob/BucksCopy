BucksCopy 서버 러너 전환 계획

목표는 Mac을 꺼도 15분봉 자동매매 판단과 주문 관리가 계속 실행되도록, macOS 앱을 실거래 실행 주체에서 서버 상태판/제어 클라이언트로 바꾸는 것입니다.

완료: AWS 계정 안전장치 완료: 15m 전용 앱 런타임 정리 다음: paper runner 배포 금지: Bitget 실거래 키 선등록

결론

지금 다음에 할 일

Lightsail 서버 기본 세팅은 끝났습니다. 다음은 repo의 server paper runner를 서버에 올려 15분봉 candle 수집, closed candle 전략 평가, heartbeat/status 저장을 검증하는 단계입니다. 아직 Bitget API key, secret, passphrase는 서버에 넣지 않습니다.

앱 수정 순서

앱부터 뜯지 않습니다. 서버에 paper runner와 상태 API가 먼저 생긴 뒤, 앱을 서버 상태 조회/ON-OFF 클라이언트로 바꿉니다.

실거래 전환은 마지막 단계입니다. 서버 러너가 15분봉 candle, heartbeat, status, restart recovery를 안정적으로 처리하는지 먼저 확인해야 합니다.

  • 완료

  • 완료
    앱 런타임은 15분봉 중심으로 단순화했습니다. Dashboard/Live 경로는 15m closed candle 기준이며, higher timeframe REST/WS 런타임 의존은 제거하는 방향으로 정리했습니다.
  • 검증

바로 다음 작업

1. Paper runner 파일 배포

  1. repo의 Server/ Docker 구성을 서버 작업 폴더에서 빌드합니다. paper runner는 Python 컨테이너로 실행됩니다.
  2. 서버의 ~/bucks-copy-server/app 아래에서 Docker Compose를 실행합니다.
  3. 첫 실행은 paper mode이며 private Bitget API를 호출하지 않습니다.
cd ~/bucks-copy-server/app/BucksCopy
cp Server/env.paper.example .env
docker compose -f Server/docker-compose.paper.yml up -d --build

2. Runner 상태 확인

  1. Docker 로그에서 15m candle 저장과 paper 평가 summary를 확인합니다.
  2. JSON/JSONL 상태 파일이 /home/ubuntu/bucks-copy-server/data 아래 생성되는지 봅니다.
  3. 24시간 동안 heartbeat와 candle update가 끊기지 않는지 검증합니다.
docker compose -f Server/docker-compose.paper.yml logs -f
ls -lah ~/bucks-copy-server/data
이 단계에서 AWS access key, Bitget API key, secret, passphrase를 입력하지 않습니다. 서버 기본 세팅과 paper runner 준비가 끝난 뒤 별도 secret 저장 절차로 옮깁니다.

데이터 기준

런타임 전략 판단은 15분봉 closed candle만 사용합니다. 진행 중인 candle은 진입 판단에 쓰지 않습니다.

앱 책임

앱은 Bitget에 직접 주문하지 않고, 서버의 status/log/on-off API만 호출합니다.

서버 책임

서버가 candle 수집, 전략 평가, 주문 실행, TP/SL 보호주문, fail-closed 처리를 소유합니다.

위험도 리스크 왜 문제인가 대응

Critical TP/SL 보호주문 실패 진입 후 포지션이 무방비 상태로 남을 수 있습니다. 보호주문 최소 5회 재시도, 실패 시 경고 후 fail-closed 시장가 청산.
High 러너 중복 실행 같은 signal에 대해 주문이 두 번 나갈 수 있습니다. 서버 단일 process lock, DB 기반 candle/signal idempotency 적용.
High 서버 재시작 후 포지션 상태 불일치 서버가 실제 Bitget 포지션과 다른 상태로 판단할 수 있습니다. 부팅 시 Bitget position/order reconciliation을 먼저 수행.
Medium 15분봉 candle 누락 전략 판단 시점이 밀리거나 signal이 빠질 수 있습니다. WebSocket 보조, 3초/주기 REST 재확인, startup gap fill 적용.
Medium 앱 ON/OFF 반영 지연 사용자가 끈 뒤에도 한 번 더 평가될 수 있습니다. runner 평가 직전 automation state를 재조회하고 변경 이력을 기록.
Low HTTPS 인증서 만료 앱이 서버 API에 접속하지 못할 수 있습니다. Caddy 또는 certbot 자동 갱신, 만료 알림 설정.

검증과 롤백

검증 기준

  • 서버가 24시간 이상 재시작 없이 heartbeat를 남깁니다.
  • 15분봉 closed candle이 누락 없이 저장됩니다.
  • paper signal과 기존 백테스트 조건이 같은 candle boundary를 사용합니다.
  • ON/OFF 상태가 runner 평가 직전에 반영됩니다.
  • 실거래 전 protection order와 fail-closed 시나리오 테스트가 통과합니다.

롤백 기준

  • 서버 runner는 paper mode부터 시작합니다.
  • 기존 macOS 앱 실거래 경로는 서버 검증 전까지 제거하지 않습니다.
  • 서버 상태가 불안정하면 automation OFF로 두고 candle/log 수집만 유지합니다.
  • 실거래 키 등록 전 단계에서는 서버를 삭제해도 거래 영향이 없습니다.
다음 대화에서 필요한 것은 Lightsail 브라우저 SSH에 접속한 뒤 나온 Ubuntu 버전과 Static IPv4뿐입니다. AWS 비밀번호, SSH private key, Bitget API secret은 공유하지 않습니다.
